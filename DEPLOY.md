# Публикация тестового стенда

Бесплатно и без карты: **Vercel** (приложение) + **Turso** (база).
Оба дают постоянную ссылку, которую можно разослать людям.

Почему не просто «залить на хостинг»: база лежала в файле `data.db`, а на
Vercel файловая система живёт только до конца запроса. После первого же деплоя
все заявки исчезли бы. Turso — тот же SQLite, но по сети, поэтому в коде
поменялся один драйвер, а схема и запросы остались прежними.

---

## 1. База на Turso

В панели https://app.turso.tech:

1. **Create Database** → имя `mizon`, регион ближе к Таджикистану
   (`Frankfurt` или `Mumbai`).
2. На странице базы скопируйте **Database URL** — он вида `libsql://mizon-komilovsg.turso.io`.
3. Там же **Create Token** (право Read & Write) — скопируйте токен целиком.

Бесплатный тариф: 500 баз, 9 ГБ, 1 млрд чтений в месяц. Для стенда с запасом.

## 2. Залить схему и данные в облачную базу

В терминале, в папке проекта. Подставьте свои значения:

```bash
export TURSO_DATABASE_URL="libsql://mizon-komilovsg.turso.io"
export TURSO_AUTH_TOKEN="ваш-токен"

npx drizzle-kit push      # создать таблицы
npx tsx lib/db/seed.ts    # дилеры, номенклатура, пользователи
npx tsx lib/db/demo.ts    # история отгрузок, чтобы отчёты не пустовали
```

Проверить, что данные легли:

```bash
npx tsx -e "import {db,schema} from './lib/db'; db.select().from(schema.users).then(r=>console.log(r.length,'пользователей'))"
```

## 3. Приложение на Vercel

Репозиторий уже на GitHub: `komilovsg/mizon`.

1. https://vercel.com → **Add New → Project** → импортировать `mizon`.
2. Framework определится сам (Next.js). Ничего не меняйте.
3. **Environment Variables** — добавьте четыре:

| Имя | Значение |
|---|---|
| `SESSION_SECRET` | длинная случайная строка, получить: `openssl rand -base64 32` |
| `TURSO_DATABASE_URL` | `libsql://mizon-komilovsg.turso.io` |
| `TURSO_AUTH_TOKEN` | токен из шага 1 |
| `SHOW_DEMO_LOGINS` | не задавайте. Кнопки быстрого входа показываются сами; `0` их прячет |

4. **Deploy**. Через пару минут будет ссылка вида `mizon.vercel.app`.

Из терминала то же самое:

```bash
vercel link
vercel env add SESSION_SECRET production
vercel env add TURSO_DATABASE_URL production
vercel env add TURSO_AUTH_TOKEN production
vercel --prod
```

Дальше каждый `git push` в `main` разворачивается сам.

## Что сказать тестерам

На странице входа четыре кнопки — «Диспетчер», «Дилер», «Охрана», «Весовщик».
Одно касание, и человек внутри: телефон и PIN подставляются сами.

Если нужно войти вручную, PIN у всех `1111`:

| Роль | Телефон | Что смотреть |
|---|---|---|
| Диспетчер | +992900000001 | доска, заявки, отчёты, дилеры |
| Дилер | +992900000002 | создать заявку со своего телефона |
| Охрана | +992900000003 | КПП: найти по госномеру, впустить и выпустить |
| Весовщик | +992900000004 | записать вес машины на территории |

Попросите открыть с телефона и добавить на домашний экран — приложение
ставится как обычное, без адресной строки.

## Чего этот стенд не умеет

- **Обмена с 1С не будет.** Из облака до 1С в локальной сети завода не
  достучаться. События копятся в очереди `outbox` и никуда не уходят — это
  нормально и ничего не ломает. Обмен включается, когда приложение переедет на
  сервер рядом с 1С.
- **Это не продовый контур.** Ссылку знает кто угодно, PIN-коды простые,
  регистрация дилеров открыта. Не заводите здесь настоящих контрагентов и
  настоящие отгрузки.

## Когда стенд пора менять на боевой

Приложение должно стоять **в локальной сети завода**, рядом с 1С: обычный
сервер или мини-ПК, Docker или `pnpm build && pnpm start` за nginx, база — файл
на диске с ночным бэкапом. Vercel нужен ровно для того, чтобы показать людям и
собрать замечания.

Ещё на боевом контуре:

- `SESSION_SECRET` другой, не тот, что на стенде;
- PIN-коды заменить и хранить хешем (в коде помечено `ponytail:`);
- вместо `drizzle-kit push` перейти на `drizzle-kit generate` + `migrate`,
  чтобы миграции были файлами и не спрашивали подтверждений;
- `SHOW_DEMO_LOGINS=0`, чтобы убрать кнопки быстрого входа со страницы.
