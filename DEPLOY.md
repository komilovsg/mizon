# Публикация тестового стенда

Бесплатно и без карты: **Vercel** (приложение) + **Turso** (база).
Оба дают постоянную ссылку, которую можно разослать людям.

Почему не просто «залить на хостинг»: база лежала в файле `data.db`, а на
Vercel файловая система живёт только до конца запроса. После первого же деплоя
все заявки исчезли бы. Turso — тот же SQLite, но по сети, поэтому в коде
поменялся один драйвер, а схема и запросы остались прежними.

---

## 1. База на Turso

В панели https://app.turso.tech:

1. **Create Database** → имя `mizon`, регион ближе к Таджикистану
   (`Frankfurt` или `Mumbai`).
2. На странице базы скопируйте **Database URL** — он вида `libsql://mizon-komilovsg.turso.io`.
3. Там же **Create Token** (право Read & Write) — скопируйте токен целиком.

Бесплатный тариф: 500 баз, 9 ГБ, 1 млрд чтений в месяц. Для стенда с запасом.

## 2. Залить схему и данные в облачную базу

В терминале, в папке проекта. Подставьте свои значения:

Vercel миграции не запускает — схему в базу заливают один раз, руками.

```bash
export TURSO_DATABASE_URL="libsql://mizon-komilovsg.turso.io"
export TURSO_AUTH_TOKEN="ваш-токен"

pnpm db:setup   # таблицы + пользователи + номенклатура + история за 30 дней
```

Проверить, что всё легло, — теми же переменными, что стоят на Vercel:

```bash
pnpm db:check
```

Он печатает, в какую базу смотрит и сколько там пользователей, дилеров и заявок.
Если видите строку «Это локальный файл» — переменные `TURSO_*` не подхватились,
и на Vercel приложение будет так же смотреть в пустоту.

## 3. Приложение на Vercel

Репозиторий уже на GitHub: `komilovsg/mizon`.

1. https://vercel.com → **Add New → Project** → импортировать `mizon`.
2. Framework определится сам (Next.js). Ничего не меняйте.
3. **Environment Variables** — добавьте четыре:

| Имя | Значение |
|---|---|
| `SESSION_SECRET` | длинная случайная строка, получить: `openssl rand -base64 32` |
| `MIZON_DB_URL` | `libsql://mizon-komilovsg.turso.io` |
| `MIZON_DB_TOKEN` | токен из шага 1 |

4. **Deploy**. Через пару минут будет ссылка вида `mizon.vercel.app`.

Переменные читаются во время сборки. Если добавили их после деплоя —
нажмите **Redeploy**, иначе приложение продолжит работать со старыми.

Если на входе появляется «Что-то сломалось», спросите у самого приложения:

```
https://ваш-проект.vercel.app/api/health
```

Он отвечает, видит ли сервер переменные и что лежит в базе; токен не раскрывает.
`"tables": []` — схему не заливали, вернитесь к шагу 2. `"ПУСТО"` у переменной —
её не видит сборка, впишите значение и нажмите **Redeploy**.

Перед боевым контуром задайте `HEALTH_TOKEN` — эндпоинт закроется и будет
отвечать только на запрос с заголовком `Authorization: Bearer <токен>`.

### Почему переменные названы `MIZON_DB_*`, а не `TURSO_*`

Интеграция Turso в Vercel сама создаёт `TURSO_DATABASE_URL` и подставляет туда
адрес вида `libsql://dpl-…-vercel-icfg-….turso.io`. Префикс `dpl-` — это **ветка
базы под конкретный деплой**: у неё свой снимок данных, и всё, что внесли
пользователи, остаётся в старой ветке после следующей выкладки. Заявки тестеров
просто исчезают, причём молча.

Поэтому приложение читает сначала `MIZON_DB_*` и только потом `TURSO_*`. Свои
переменные интеграция не трогает, так что постоянная база задаётся через них.
Проверить, какая база используется, можно на `/api/health` — он печатает строку
`источник`.

Не проверяйте переменные через `vercel env pull`: старые версии CLI отдают
пустые значения для зашифрованных переменных, и это уводит по ложному следу.

Из терминала то же самое:

```bash
vercel link
vercel env add SESSION_SECRET production
vercel env add TURSO_DATABASE_URL production
vercel env add TURSO_AUTH_TOKEN production
vercel --prod
```

Дальше каждый `git push` в `main` разворачивается сам.

## Что сказать тестерам

Входа в программе нет: она рассчитана на работу внутри завода, где посторонних
за экраном не бывает. Человек открывает ссылку и сразу оказывается в деле.

| Кому | Что смотреть |
|---|---|
| Менеджер | «Создать заявку» — большая кнопка на главной |
| Диспетчер | доска машин, отчёты за 30 дней, справочник контрагентов |
| Охрана | КПП: найти по госномеру, впустить и выпустить |
| Весовщик | доска: открыть машину на территории и записать вес |

Попросите открыть с телефона и добавить на домашний экран — приложение
ставится как обычное, без адресной строки.

## Чего этот стенд не умеет

- **Обмена с 1С не будет.** Из облака до 1С в локальной сети завода не
  достучаться. События копятся в очереди `outbox` и никуда не уходят — это
  нормально и ничего не ломает. Обмен включается, когда приложение переедет на
  сервер рядом с 1С.
- **Это не продовый контур.** Входа в программе нет, а ссылка открыта в
  интернете: заявку может создать любой, кто её знает. Не заводите здесь
  настоящих контрагентов и настоящие отгрузки.

## Когда стенд пора менять на боевой

Приложение должно стоять **в локальной сети завода**, рядом с 1С: обычный
сервер или мини-ПК, Docker или `pnpm build && pnpm start` за nginx, база — файл
на диске с ночным бэкапом. Vercel нужен ровно для того, чтобы показать людям и
собрать замечания.

Ещё на боевом контуре:

- `SESSION_SECRET` другой, не тот, что на стенде;
- закрыть доступ снаружи: программа рассчитана на локальную сеть завода, в
  интернете её адрес открыт любому, кто его знает;
- вместо `drizzle-kit push` перейти на `drizzle-kit generate` + `migrate`,
  чтобы миграции были файлами и не спрашивали подтверждений;
